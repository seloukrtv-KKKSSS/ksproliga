# Голосування «Лев матчу» у vMix / OBS

Адреса залишається `/obs/lion-voting?matchId=ID`, де `ID` — номер матчу. Посилання можна скопіювати з панелі керування голосуванням.

## Налаштування трансляції

1. Додайте Web Browser у vMix та вставте посилання.
2. Встановіть **450 × 360 px**. Картка має ширину 420 px і прозоре поле навколо. Старий розмір 450 × 650 теж працює, але залишає більше порожнього місця.
3. Позицію віджета задайте через Input Settings → Position. Не потрібно рендерити браузер у 1920 × 1080 тільки для розташування невеликої картки. vMix підтримує окремий розмір браузера та його позицію: [Web Browser у посібнику vMix](https://www.vmix.com/help29/WebBrowser.html).
4. Після встановлення цієї версії один раз перезавантажте джерело браузера, щоб воно отримало нову сторінку.

За замовчуванням результати перевіряються кожні **5 секунд** після завершення попереднього запиту. Відображення може відставати на цей інтервал плюс час мережі.

| Адреса | Інтервал | Призначення |
| --- | --- | --- |
| `?matchId=ID` | 5 с | Звичайний ефір |
| `?matchId=ID&refresh=10` | 10 с | Менше мережевих запитів та оновлень |
| `?matchId=ID&refresh=2` | 2 с | Швидше відображення голосів |

Параметр `refresh` задається в секундах і обмежений діапазоном 2–60. Він не змінює FPS браузера або всієї трансляції.

## Що змінено

- Окремий HTML Route Handler обходить React/Next на клієнті, спільний layout, аналітику, PWA та клієнт Supabase. У браузері завантажується один невеликий скрипт без залежностей.
- Темна непрозора картка, золотий акцент лідера, системний шрифт, монограми команд. Зображення, зовнішні шрифти, анімації, переходи, розмиття та постійний цикл малювання відсутні.
- Сервер рахує відсотки серед **усіх видимих кандидатів**, повертає лише топ-3 та загальну кількість голосів. При однакових результатах порядок визначає ID. Приховані кандидати виключені з суми.
- Один послідовний запит замість WebSocket і паралельного резервного опитування. Голоси, які надійшли між перевірками, відображаються разом. Виправлено стару ситуацію, коли резервне опитування запускалося через 8 секунд навіть за справного WebSocket.
- `ETag` / `304` дозволяє пропускати JSON та зміни рядків, якщо результат той самий. При зміні скрипт торкається лише текстів і смужок, значення яких змінилися. Три DOM-рядки використовуються повторно.
- Запити мають тайм-аут. При збоях інтервал повторів зростає до 60 секунд, останні результати залишаються на екрані. Після повторної помилки з’являється статичний напис «НЕМАЄ ЗВ’ЯЗКУ». Після відновлення мережі синхронізація поновлюється; заміни на тестові голоси немає.
- `document.hidden` не зупиняє оновлення: вбудований браузер може вважати джерело прихованим, коли vMix ще захоплює його. При закритті сторінки запити й таймери скасовуються.
- Service worker сайту пропускає `/obs/`, щоб не повертати збережену сторінку замість актуальних результатів. Новий оверлей сам не реєструє service worker.

## Перевірка

`pnpm test:lion-voting` перевіряє підрахунок, прихованих кандидатів, незмінні відповіді, помилки мережі та життєвий цикл браузера. Загальна перевірка проєкту: `pnpm check`.

Для інтеграційної перевірки потрібні справжні `NEXT_PUBLIC_SUPABASE_URL` і публічний anon/publishable ключ. Без конфігурації API повертає 503 та не показує вигаданих результатів. API читає дані з правами `anon`; ключ `service_role` не використовується.

У vMix порівнюйте навантаження за однакових розмірів джерела, сцени й налаштувань ефіру: без віджета, зі статичними результатами та під час голосування. Код усуває зайву роботу сторінки, але захоплення браузера й композиція кадрів у vMix усе одно потребують ресурсів; нульове використання CPU не гарантується.
